# 活用链重构当前状态评估

## 结论

当前工作没有达到重构完成，也不能称为完整的新架构。已经完成的是第一阶段基础：六类实体的设计契约、补助规则资源的初步拆分、插入语回归修复、规则树展示原型，以及对现有 Rust 和前端的兼容接入。旧状态机仍然是运行主体，新架构的关键执行语义尚未建立。

按用户要求衡量，当前完成度约为 25%～30%。这个比例包含已经落地的基础代码和资源迁移，不包含只写在配置或文档中的声明。

## 尚未完成的核心部分

### 六类还没有六套真正的执行器

配置中已经写入 `verb_cycle`、`i_adjective_conversion`、`na_adjective_judgement`、`classical_conjugation`、`auxiliary_verb` 和 `insertion`，但代码仍主要使用旧的 `Core`、`Attach`、`Support`、`Boundary`、`Stop` 转移。

目前只有插入语获得了相对独立的执行路径。其余五类仍未形成各自的：

- 输入状态判定；
- 接续许可；
- 输出词性与活用形转换；
- 递归或有限循环策略；
- 停机条件；
- 证据和冲突处理。

因此，当前“六类”主要是分类元数据，尚未成为运行时架构。

### 阶段顺序没有进入状态机

文档已经记录：

```text
使役被动 → て形与补助动词 → 主观愿望 → 极性与礼貌 → 时态 → 句末认识／推量
```

规则已经具备阶段、执行器、输入／输出类别、停机方式和排序值；状态机也会记录逆序接续冲突并将结果降为 candidate。更细的 `allowed_after`、`same_layer` 和每条规则的严格阶段约束仍需继续补全。

这意味着长链只能在已有特例覆盖的范围内工作，尚未具备可扩展的顺序约束。

### 词性转换没有真正执行

`ない`、`たい` 等仍然主要按旧 operator 方式附加。状态机还没有可靠地执行以下整体转换：

```text
动词未然形 + ない → イ形容词性整体
动词连用形 + たい → イ形容词性整体
たい + ない／た → イ形容词活用
そう／よう／みたい／べき／はず → ナ形容词词干或判断结构
判断结构 + だ／だった／で／な → 判断收尾
```

因此，当前状态仍不足以支撑“前项和自身共同改变为新词性和新活用形”的要求。

### 文言活用尚未实现

文档提到了ク活用、シク活用、ナリ活用、タリ活用、`ごとし／ごとき` 等形式，但代码中还没有独立文言活用表和文言执行器。现代语的 `ようだ` 与文语形式的边界也还没有进入运行时判定。

### 补助动词仍只完成第一层

`て／で + 补助动词` 的一层连接已经保留父链和子链，但下面内容仍未完成：

- 补助动词自身继续活用；
- 补助动词再接补助动词；
- `読み始める`、`読み出す`、`読みすぎる` 等连用形补助统一进入同一执行器；
- `たり`、连用形、其他规定连接器的统一处理；
- 补助层与否定、礼貌、时态、句末推量的严格组合；
- 补助层无限扩展时的边界和停机。

当前实现可以覆盖部分已有案例，尚未形成你要求的可拓展补助动词递归模型。

### `て` 与补助词本体的关系还没有完全收束

配置源和 grammar catalog 已经删除 `て` 开头的独立 entry；旧构式概念只保留为 deprecated redirect，搜索索引和运行时 operator 已改为 `いる／しまう／おく／ゆく` 等补助动词本体。前端规则资源仍需继续补齐其余补助形式的统一概念映射。

正确的最终模型应当是：

```text
て：独立的接续成分
おく：独立的补助动词词条
て + おく：由 te_connection 条件和 おく 规则生成
```

`ておく`、`てしまう`、`ている` 可以作为规则的代表形式和命中范围，但不能继续作为词条实体。编译目录、搜索索引、查询路由和展示标签都需要统一到这一模型。

### 插入语范围仍然过宽

当前初步分类函数会按 `助詞` 大类将成分归入插入语类，这与当前范围不一致。一般叹词和普通格助词不应进入此次活用重构；只有承担以下作用的成分才进入规则输入：

- 名词化；
- `のだ` 等解释结构；
- `は／も／だけ／さえ／こそ` 等插入或范围保持；
- 已声明的活用接续边界。

最终应改为显式白名单和上下文条件，不能将所有助词统一归类。

### 规则树还不是实际运行树

当前气泡显示的是配置中的静态摘要，尚未根据当前命中动态投影：

- 实际输入词性；
- 实际前接活用形；
- 命中的规则组；
- 输出词性；
- 被跳过的阶段；
- 插入语节点；
- 句末、中顿或继续接续状态。

因此，它已经具备“可读树”的外观，还没有成为真实状态机的解释视图。

### 旧词条全集还没有逐项迁移

目前只处理了 `te_*` 补助资源这一组。旧有的助动词、形容词转换、判断、文言、连用复合和补助规则还没有逐词条确认：

- 新实体类别；
- 输入条件；
- 输出状态；
- 阶段位置；
- 停机方式；
- 规则代表形式；
- 词条归属；
- 例句和术语。

“旧词条都已经在新架构中正确支持”目前没有证据可以成立。

## 当前架构的自洽程度

当前架构属于过渡状态，存在三处明显的不自洽：

1. 配置源已经把 `て〜` 形式拆成规则和补助词本体，编译 grammar catalog 和 search index 仍保留旧的 `〜て〜` 构式资源。
2. 配置声明了六类专用执行器，运行时仍以旧的统一转移枚举为主体。
3. 文档将一般格助词排除在范围外，分类函数仍然按助词大类进行初步归类。

这些问题不会一定导致当前测试失败，因为现有测试主要验证旧状态机的案例和资源可解析性，尚未验证新架构的完整契约。

## 后续必须完成的顺序

### 第一阶段：收束资源边界

删除并重新生成所有 `て` 开头的词条入口，只保留：

- `て` 的接续规则或连接器定义；
- `いる`、`ある`、`しまう`、`おく` 等补助动词本体；
- `te_*` 规则的语义资料、代表形式和组件引用。

编译目录、搜索索引、前端内置查询和词条类型必须使用同一来源。

### 第二阶段：建立统一规则 schema

规则至少需要声明：

```text
rule_id
entity_class
executor
input_state
accepted_forms
accepted_categories
consumes
output_state
output_category
stage
order_constraints
terminal_mode
representative_examples
evidence_requirements
```

阶段字段属于规则，不能回写为六类实体。

### 第三阶段：实现六类专用执行器

实现顺序应为：

1. 动词循环执行器；
2. イ形容词转换执行器；
3. ナ形容词判断执行器；
4. 补助动词递归执行器；
5. 插入语零状态执行器；
6. 文言活用执行器。

每个执行器完成后，分别补充模块文档、术语表和最小代表例句。

### 第四阶段：接入阶段顺序和停机

为规则增加阶段约束、同层组合、可跳过层、停机方式和冲突诊断。长链需要验证：

```text
使役／被动 → 补助层 → 愿望 → 否定／礼貌 → 时态 → 句末推量
```

### 第五阶段：逐词条覆盖

重构完成前必须建立旧词条到新规则或新词条的映射表，逐项处理缺失项。每份提交至少完整解决一个可复现问题，并记录输入、识别链、预期状态、实际状态和术语说明。
