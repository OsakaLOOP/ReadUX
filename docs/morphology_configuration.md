# 活用链配置

全部 operator 在 connection_types 中采用统一的接续结构分类，分别为直接接续、连接器接续、连续词尾、谓语构式、词内活用和插入成分。路径分支、语法成员和前项依赖数量分别维护。connection_rules 为每个条目提供直接路径或连接器引用；文言路径的 source 对应 classical_auxiliaries.inputs，义务和禁止构式对应 predicate_links.prefix。新增的词类分组使用 exact_category 保留名词谓语等原始类别，既有判断兼容路径继续共享判断词尾的接续条件。

连接器接续保存连接器之前的输入状态和连接器本身，如「动词连用形＋て／で＋おく」；三个缩约补助形式采用相同的结构分类。connector_alternatives 声明同一用法的其他连接器入口，「になる」同时引用名词后的格助词に和形容动词的连用形に。分析结果的 dependency_type 表示结构类别，predecessor_range 定位具体路径的前项，context_range 与 context_surface 保留包含连接器及合法插入项的上下文。

词内活用的路径声明 scope: inflection，依据自身实际活用状态定位；插入路径通过 evidence 对应执行器已经确认的位置。词条的 variants.concept 按具体成员身份选择讲解，例如名词化の与接尾辞さ分别引用对应正文。

维护约定见 [第 11 阶段展示规范](morphology_stage11_bubble_display.md)。完成修改后可运行 python -X utf8 scripts/check_morphology_connections.py，检查全部条目的分类、路径、连接器、概念正文、例句以及既有路径引用。检查脚本只读取资源。

唯一规则入口为 `configs/unidic-nlp/morphology.json`。Rust 编译时嵌入配置，前端直接导入同一文件；配置内容参与分析缓存标识。修改后重新构建应用即可更新分析和展示。

「意向形＋と＋する」通过 `volitional_to_connection` 保留意向接续，再由 `volitional_to_suru` 建立补助子链。「する」采用自身的活用，可继续连接「ている」等形式；普通引用「と」保留独立身份。

「しか＋ない」由连续词尾按后项「ない」的实际活用形识别为 `shika_nai`，输出形容词状态，支持「しかなかった」「しかなくなる」「しかなくない」等后续变化。「こと」采用 `koto_nominalization` 输出名词词干，并沿用格助词「に」与「なる」的补助连接。名词化规则依据执行器身份优先于外部整体词界。

「ていい／てよい」「ていただく」「てかかる」共用て形补助入口；后项分别采用形容词、动词、动词活用。「なくていい」的否定属于前项，「いい」可继续连接解释语气「んだ」与原因接续。「てかかる」表示以前项所示态度应对某事，原始词性和补助功能分别保存。七句验收见 [谓语接续例句验收](morphology_predicate_examples_2026-10-27.md)。

规则合法性依据当前状态与后项词法条件。`stage`、`order_rank` 保留展示信息；`input_categories`、`input_forms` 及 `exclude_input_ctypes` 定义局部输入约束。活用型排除采用精确匹配，「助動詞-タ」与「助動詞-タイ」分别处理。补助词的输入条件针对前项，输出状态采用后项自身活用；名词化与词性转换后继续使用新状态。

`operators` 按形式身份定义概念目录路由、标题、原型、候选解释及输出状态。`variants` 按顺序选择原型；`normalized` 用于具有固定展开形式的缩约和补助结构。原始表记、成员及来源字段保存在分析对象中。补助用言的 `support` 声明词元和连接组，`connector` 指向前项接续形式，`compound_candidate` 控制整体查词候选。

`support.group` 为 `contracted` 的实际缩约显示“缩略形式”标签，文案由 `presentation.contraction_label` 定义。原型和规范化字段用于形式展示及查询，缩约身份由连接组明确指定。

`title` 使用中文语法名称，气泡副标题使用日语原型。例如「进行／状态持续 · ている」「完成／遗憾 · てしまう」；缩略形式共享对应的中文标题，日语原型与实际缩略词形分别用于副标题和推导步骤。

`presentation.phenomena` 根据活用形和显式识别证据生成现象标签。四类音便分别采用 UniDic 的イ音便、促音便、撥音便、ウ音便字段。「なきゃ／なけりゃ」等融合形式归为口语缩略，统一显示“缩略形式”。普通可能形保留可能活用说明。

缩略形式的日语副标题沿用规范原型，步骤输出保留缩略，后续步骤直接承接该输出。例如义务形式副标题为「なければいけない」，推导为「謝ら → 謝らなきゃいけない」，后续名词化为「謝らなきゃいけない → 謝らなきゃいけないの」。缩略补助动词需要继续屈折时，步骤采用其缩略基本表记，例如「読んじゃう → 読んじゃった」。

`features` 从单个 UniDic token 识别形式，`exclude` 排除与完整形式重叠的基础功能，例如「たら」采用条件形式。`connections` 决定相邻成员的核心归属、附属或补助链关系。连接规则按顺序执行；一条规则内的 `when` 为任选条件，每个条件内的字段同时成立。`equals`、`starts_with`、`contains` 的同字段取值为任选。`following` 检查后续 token，`at_end` 检查输入终点，适用于区分句末「の」与「のだ／のが」。`stop` 明确保留成员边界。已知形式应明确规定前接形及词类，来源关系用于辅助判断归属。字符不连续、空白和标点由执行器统一限制。

`forms` 映射 UniDic 活用形。`insertion` 以词性、基本表记和助词小类共同限定成员，实体分类与运行匹配读取同一白名单。`insertion_positions` 的 categories、forms、bases 限定允许的位置；connector、support_group 声明需要完整补助连接的入口，当前对应て形。执行器核对字符连续性，并确认连接器、各插入成员和补助词对同一谓词的 GiNZA 依存关系。

插入成员及各自 operator 保存在原所属链内，词汇核心、查询原形、词性、活用形、实体身份和停机许可保持前项值。插入 occurrence 的命中范围为成分自身，上下文采用扩展后的所属链；补助 occurrence 包含连接器、全部插入成员和补助词的范围与引用。`presentation` 继续负责标签和原型接续显示。

同一活用型内的形式应按实际功能分别定义，例如 UniDic 的「助動詞-ダ」按词形及活用字段区分连用修饰「に」、连体修饰「な」和断定「だ」。`display_suffix` 控制形状词链的显示词尾；补助结构「てゆく」保留自身形式，并共享「ていく」的概念目录路由。形式身份、查询表记与概念路由可以分别配置。

「でしょう」由「助動詞-デス」与「意志推量形」共同识别为推量形式，原型为「でしょう」，概念路由沿用「です」。同一 token 的敬体和一般意向形通过 `exclude` 排除，显示采用推量形式的独立身份。

「だろう」由「助動詞-ダ」与「意志推量形」共同识别，整体原型为「だろう」，概念路由沿用「だ」。同一 token 的断定和一般意向形通过 `exclude` 排除。名词、形状词及用言的终止形、连体形均可连接；后接终助词「か」时，连续规则整体生成「だろうか」的说明和查询范围。

连续语法词尾由 `sequences` 声明，先于逐 token 的连接规则匹配。条件包含前项词形、词类及连续 token 身份；固定词尾允许内部包含助词，例如「けれど＋も」「なく＋て＋は」。`terminal_only` 限制仅在句末成立的省略结构。形式跨度精确覆盖词尾，主体词汇查询身份保持独立。

`connections.operators` 与 `sequences.operators` 匹配最近的有效语法步骤，期间的插入语保持其许可。`sequences.exclude_following` 排除会与后续接续竞争的固定词尾：例如「の＋に」后接「なる」时保留名词化与变化连接。普通逆接「のに」沿用原条件。

`sequences.head` 指定序列中提供词元与活用身份的成员，默认是首项。「の＋ごとき」的 head 为 1，命中范围覆盖完整接续，文言执行器读取ごとき的词形与活用字段。「だっ＋た」「でし＋た」共同作为 `copula_past` 执行，过去判断的范围覆盖两个成员；「だっ」「でし」保留连用形身份。

判断规则先输出词干状态，再由だ／だった／でした、で、な、に生成终止、连用或连体状态。はず保留名词词干，らしい保留イ形容词活用；接尾辞らしい采用 `rashii_characteristic` 表示典型性，助动词らしい表示推量。そう按前项词干／连用形与终止形分别记录样态、传闻证据。名词＋の＋よう／はず采用连续接续；独立名词和副词继续沿用各自词汇身份。

`classical_forms` 根据明确的词元或文语 cType、词元词尾与实际词形识别ク／シク／ナリ／タリ活用，表中词元提供代表形式，文语 cType 允许同型词推广。`classical_auxiliaries` 按词元、cType、cForm 和完整词形匹配助动词，并通过 `inputs` 的任选条件组同时校验前项 `categories`、`forms`、`ctype` 与 `exclude_ctype`。例如り分别声明サ变未然形、四段已然形两组输入；なり和たり依据意义拆分接续规则。

文言规则与其他规则共用 `operators` 和 `rule_metadata`，词条位于普通 grammar source bundle，编译目录、搜索索引和气泡查询沿用同一入口。范式与接续证据写入 operator 的 evidence；终止、连体、连用和条件等状态决定句末、从句或中顿的可停机性。验收入口为 `morphology_stages_5_6.rs`，覆盖每个已声明的词形、接续组及其输入活用形。

`predicate_links` 在后项完成自身活用后建立父链，按前项形式、后项词汇身份和否定 operator 共同确认义务或禁止。后项的敬体、过去、推量及进一步条件变化保留实际成员和独立说明。完整构式提供统一的语法命中与原型，主体词条继续查询原动词。标点、空白及缺少否定证据的后项维持原边界。「のに」保留逆接与用途、评价候选；「ないと」后项省略显示否定条件。

「ても／でもいい」「なくてもいい」采用独立的「も」成员。新增跨成分构式时，应先确定助词身份和句法范围，再决定成员归属。

经 GiNZA 确认的助词插入补助结构优先于连续词尾，例如「読んではいる」保留「ている」连接。`presentation.observed_steps` 指定按实际活用形承接的显示步骤，「ませんでした」中的「でし」按实际连用形连接后续「た」。

先采集真实分词，核对基本表记、词元、活用型与活用形，再编写规则。用正例和相邻边界的对照验证识别、父链、命中范围及查词形式；同一范围的复合形式采用独立身份，避免重复展示其内部功能。主要验证入口为 `morphology_reconstruction.rs`、`p4_language.rs` 和 `lookupPresentation.test.mjs`。

名词性接尾辞在连接状态中按名词处理，原始词性继续保存在来源 token 中。「紫陽花＋さん」形成名词核心，可继续接「じゃないから」；「つつ」连接连用形。「たり／だり」同时接受接续助词与副助词分析，后接「する／できる」形成附属链。「たりとか」接受「と＋か」与单个副助词「とか」，由 `sequences.operators` 限定前项已有列举形式，并兼容たり的终止形、连体形分析，随后继续连接「する」。

连续词尾仅在首项能够形成 `te_connection`、后续插入助词与补助动词又有 GiNZA 依存证据时，让位于て形的跨助词连接。「たりとか」保持连续词尾组合及后项父链；「読んではいる」继续采用て形插入连接。

「とか」兼容单个副助词和「と＋か」分词，可接在名词或用言的终止形、连体形后。作为插入语时，`operators.preserve_state` 保留前项的词类、活用形和接续状态，后续语法形式继续按前项接续；实际成员及范围仍完整保存。连续规则记录 `phenomenon:insertion`，展示沿用现象标签，标注“插入语”。

「は、も、さえ、こそ、だけ、まで、しか、すら、なんて、など、とか」须符合白名单的基本表记、词性和助词小类。四组位置分别覆盖て形补助连接、谓语末尾、名词后及连用形焦点成分；各组 bases 进一步限制成员。て形位置要求完整句法证据，其他位置依据已声明的词法条件执行并保存可用的来源关系。阶段 7 的验收入口为 `morphology_reconstruction.rs` 中的 `stage_seven_*` 用例。

「とか」及「と＋か」由连续词尾识别。名词、代词与谓语终止形／连体形按原条件连接，覆盖「本とか」「ですとか」「だとか」。连用形位置要求最近语法步骤为 `enumerative`，覆盖「たりとか／だりとか」；插入后继续保留「たり＋する／できる」的连接许可。「読みとか」「読んでとか」保持词法边界。空白与标点终止连续连接。

补助用言匹配同时采用基本表记和经可能形规则确认的词汇原型，例如「書ききれない」中的「きれる」按「きる」连接彻底完成形式，并保留可能活用。已识别的补助关系优先于 GiNZA 的整体词界，词界证据继续用于构词与归属确认。

名词、代词及名词化结果可接「に＋なる」；「静かに」「ように」使用形状词的连用接续。前项保留词类与查询身份，「なる」建立动词子链。「形容词／否定助动词的く形＋なる」使用同一补助执行入口。「か＋も＋しれ＋ない」按完整连续词尾识别可能性，输出形容词状态，采用「ない」的实际活用形，可继续接过去或「なる」及「てしまう」。例如「キャンセルになるかもしれなくなってしまった」按名词、变化动词、可能性、变化动词和完成补助依次连接。普通格助词「に」及孤立的「か」「も」按各自词法边界处理。

「はず／筈」依据名词词元和前项连体形连接，生成预期判断形式，输出名词状态，可继续连接「なのだから」「だった」「でしょう」等词尾。独立名词用法沿用自身查询身份。

「くらい／ぐらい」依据副助词身份及共同词元「くらい」连接，接受名词、数量和用言的终止形、连体形，生成程度／约量说明；输出名词状态，可继续连接「だ」等形式。原型按实际清浊表记选择，相同假名的形容词沿用其词法身份。

「ませ＋ん」通过连续词尾识别为 `polite_negative`，整体原型为「ません」，说明采用独立的敬体否定词条。原始成员保留「ます」未然形与否定助动词「ん」，后续「でした」继续按实际成员连接。词条说明「ぬ→ん」的撥音便关系；其他否定结构中的「ん」按实际表记选择原型。

`presentation.transition_tails` 根据后项是否在语法接续上依赖前项的词尾假名，结合语法身份、活用型、前接形及末尾假名选择提示范围。例如五段连用形接「ます」显示「み→みます」，音便形接「て／た」显示「ん→んで」「っ→った」，て形接补助用言显示「で→でいる」。一段动词接「ます」及普通名词接续仅显示完整变化。已有功能成分发生屈折时，说明保留该成分的完整词形，如「ない→なかった」。核心自身的条件形、命令形等按实际正文范围生成步骤。
