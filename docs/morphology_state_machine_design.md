# 活用链状态机重构设计

## 设计目标

活用链从 UniDic 的词干、活用形和词界结果继续构造可解释的语法链。词典词条保存词本体，接续规则保存用法；一个词本体可以被多条规则引用，同一语法构式只由规则生成。这样可以合并“てしまう”和“しまう”的重复内容，同时保留“て形＋しまう”的识别、词性变化和展示范围。

状态机需要同时满足四项约束：前项状态明确记录词性大类、活用形、活用类型和连接形；每次接续声明输入条件、输出状态、词性变化和可否停机；合法性由当前状态与后项的接续条件决定，补助词接入后采用自身活用；机器保存完整匹配证据，界面展示有名称的规则树和分类。

## 六类实体

六类是词条和识别结果的稳定分类，阶段、优先级和停机方式属于规则属性。叹词、一般格助词等本身不参与活用状态机；只有承担名词化、插入或活用接续边界的指定助词进入规则输入。

| 类别           | 输入                                     | 输出                     | 典型成员                                                       | 执行方式                                               |
| -------------- | ---------------------------------------- | ------------------------ | -------------------------------------------------------------- | ------------------------------------------------------ |
| 动词循环类     | 动词未然形、连用形或终止形               | 动词                     | せる、させる、れる、られる、ない、ぬ、ず、ます、た、う／よう   | 受限有限状态转移；输入和输出保持用言范畴，可继续连接。 |
| イ形容词转换类 | 动词连用形、未然形或前一助动词指定形     | イ形容词                 | たい、ない、やすい、にくい、らしい的一部分用法                 | 执行词性转换，切换到イ形容词活用表。                   |
| ナ形容词判断类 | 终止形、连体形、体言或指定词干           | ナ形容词词干／判断结构   | そうだ、ようだ、みたいだ、べきだ、はずだ                       | 先形成词干，再由判断词尾执行だ／だった／で／な收尾。   |

| 补助动词类     | て／で形、连用形、たり等规定连接形       | 动词或形容词，可再次循环 | いる、ある、しまう、おく、いく、くる、みる、あう、すぎる、出す | 建立父子链；补助词本体按动词活用执行，连接规则可递归。 |

“ている”“てしまう”“ておく”属于补助动词类的规则用法。词条只保留“いる”“しまう”“おく”等代表词；规则的代表形式、前接条件和语义说明指向这些词条。独立动词义项继续由普通词典词条处理。

## 不同类别的执行器

六类共享统一的 RuleInput、RuleOutput 和 Evidence 接口，匹配和执行由类别专用执行器完成。

### 动词循环执行器

动词循环执行器读取当前词类、词干、未然形、连用形、终止形以及下一项的 cType／cForm。使役、被动、可能、礼貌和时态按局部接续条件执行；否定与愿望根据规则输出形容词状态。礼貌助动词等受限前项通过精确活用型限制后续使役、愿望或重复礼貌，输入不成立时保留候选与输入诊断。

### イ形容词转换执行器

转换执行器在确认前接形后，将整体类别从动词或助动词改为イ形容词，并把后续输入交给形容词活用表。例如“読み＋たい”输出イ形容词状态，后续“たくない”“たかった”沿用同一词条的活用，而不再按动词否定处理。

### ナ形容词判断执行器

判断执行器区分词干和判断词尾。そう、よう、みたい、べき、はず等先生成ナ形容词词干或判断结构，再根据终止、连体、连用和过去规则生成“だ、な、で、だった”等形式。判断词尾的活用属于本执行器，不能混入动词循环类。

### 文言执行器

文言执行器使用单独的活用型表，至少区分ク活用、シク活用、ナリ活用、タリ活用和文语助动词。ごとし／ごとき的连体、已然等形式在文言表内判定，现代“ようだ”保持独立身份。

文言沿用普通语法的词条、operator、concept 查询、命中范围和规则树投影。每个助动词的意义与用法进入正式词条；なり的断定与传闻、たり的完了与断定分别声明规则和概念。`classical_forms` 保存可按活用型推广到其他词元的词干变化，`classical_auxiliaries` 保存助动词的完整词形及接续条件。两张表提供专用执行器需要的语言数据，执行结果仍采用统一的输入状态、输出状态和证据结构。

接续条件同时判断前项类别、活用形和活用型，允许一条规则包含多组条件。例如り接サ变未然形或四段已然形，べし等接一般终止形或ラ变型连体形。词形与条件匹配后，整个链切换为文语用言状态，后续助动词继续读取实际活用形。现代べき后接だ／です及其活用时形成判断词干；独立的べし、べく和连体形べき保留文言词条归属。

### 补助动词执行器

补助执行器先确认连接器，再建立父链和子链。て／で形、连用形、たり等连接器由专门连接规则判断；补助词本体保留动词词元、活用和查询形，整体构式的命中范围覆盖连接器与补助词。子链完成后可以继续进入动词循环、形容词转换或下一层补助连接，直到句末或中顿停机。

运行时按补助规则声明的连接组校验前项类别、连接形和字符范围。连接器继承前项状态，只更新连接形；子链保留补助词本体的查询形，并记录连接规则证据。递归上限按父子链中的补助构式计数，不计连接器。输入、连接器、范围或深度校验失败时，链保持候选状态，句法归属证据保留为独立证据。

所有带 `support` 的规则统一使用补助执行器，包括「たり＋する／できる」「名词性成分＋に＋なる」和「く形＋なる」。子链采用后项自己的 cType／cForm；「なる」「する」输出动词，「ほしい」与完整否定构式输出形容词。缩约的「ちゃう／てる／とく」沿用展开动词的类别及查询身份。前项名词、代词或名词化结果保留自身类别，「に」仅设置变化连接形。

### 插入语执行器

插入执行器由规则元数据选择。成员白名单统一控制实体分类与运行匹配；位置声明按词性、活用形和词元限定谓语末尾、名词后、连用形中的焦点成分，以及て形后的补助连接。て形位置还须完整确认连接器、全部插入成员和补助词对同一谓词的 GiNZA 依存关系，字符范围保持连续。

插入成员直接增加到所属链的范围中，每项生成独立 operator，保存原输入、扩展后的词面、完整前后状态及可用的 case／mark 来源证据。词汇核心、查询原形、阶段顺序和停机许可沿用前项，后续活用继续读取原状态。多个连续插入成员依次执行，补助词仍以原所属链为父链，递归深度只统计补助构式。

插入 occurrence 保留成分自身的命中范围，context_range 提供扩展后的所属链上下文；补助 occurrence 按正文顺序组合连接器、各插入成员和补助词的范围、成员与 operator 引用。举例形式とか及と＋か共用本执行器，名词化の和判断词尾仍分别执行自身的状态变化。例如「気付きたくなかっただけなのだ」中的だけ保持形容词性，な、の、だ依次完成判断接续、名词化和断定。

## 状态与规则

状态记录词性、活用形、活用类型、活用形式和六类实体身份。阶段只作为可选规则约束，不作为分类字段：

```text
MorphologyState
├─ category: 動詞／形容詞／形状詞／助動詞／名詞／文語用言
├─ form: stem／irrealis／continuative／terminal／attributive／conditional／imperative／volitional／te／other
├─ conjugation_type: UniDic cType
└─ entity_class: 六类之一
```

每条规则声明 rule_id、label、group_name、entity_class、输入条件、消耗 token、输出状态、可选阶段约束、前后顺序、停机方式、代表输入和证据来源。执行后，前项与当前项形成一个整体状态；助动词“ない”输出イ形容词性状态，“ます”接“しょう”后输出终止状态，“しまう”通过补助规则保持动词循环类并可继续接“た”“ない”。

## 规则顺序与停机

阶段和 `order_rank` 用于说明与展示；分析执行采用当前词类、活用形、活用型及紧邻连接器判断合法性。「たりする」后接否定、「かもしれない」变为「かもしれなかった／かもしれなくなる」、过去后名词化再接判断均由这些局部条件处理。规则中保留的数字阶段不构成全链递增要求。

`connections.operators` 与 `sequences.operators` 指向最近的有效语法步骤，插入语保持该步骤的接续许可。历史连接器已用于接入其他谓词时，其许可随新状态结束。`exclude_input_ctypes` 精确排除当前活用型，例如「助動詞-タ」与「助動詞-タイ」分别判定；固定词尾的 `exclude_following` 可保留后续构式需要的内部成员。

停机方式分为句末、从句末和中顿三种，插入语保持前项停机状态。合法的后续接续继续读取局部输入条件。设计审计、语言依据及回归结果见[局部接续验收](morphology_local_connections_2026-10-27.md)。

## 可读规则树

机器规则可以穷举 UniDic 条件，展示树使用命名节点和代表分支。每个节点包含 label、summary、input_examples、output 和 children；children 只保留两到三个代表分支，其余条件折叠为“同类条件”。

```text
动词循环类
├─ 未然形输入
│  ├─ 五段 → ない／せる／れる
│  └─ 一段・变格 → ない／させる／られる
├─ 连用形输入
│  ├─ 礼貌层 → ます
│  └─ 补助层入口 → て／で + 补助动词
└─ 终止形收尾
   ├─ 意向 → う／よう
   └─ 禁止或推量 → まい／だろう

补助动词类
├─ て形接续
│  ├─ 持续与状态 → いる
│  └─ 完成与遗憾 → しまう
├─ て形接续
│  ├─ 预先处置 → おく
│  └─ 趋向与变化 → いく／くる
└─ 连用形接续
   ├─ 开始、继续、结束 → 始める／続ける／終わる
   └─ 程度、反复、相互 → すぎる／出す／あう

插入语类
├─ 对比与提示 → は／も
├─ 限定与强调 → だけ／さえ／こそ
└─ 列举与举例 → など／とか
```

树中显示输入类别和代表形式，不显示每个表记、音便和词典别名。点击节点后再展示完整条件、命中 token、句法证据和词性变化。

## 词条、展示和迁移

configs/grammar/auxiliaries.json 保存独立词条和补助用法说明，configs/grammar/migrations/te_construction_ids.json 保存历史 ID 与规则兼容元数据，前端查询将构式命中映射到补助词本体。迁移资源中的 headword 不作为正式词条入口；te_shimau 等规则只保存 operator、代表形式、连接器 te_connection、支持词“しまう”和语义说明。

活用气泡正文下方增加“接续条件”区域，与例文左右分栏，例文列宽略大。接续区域使用白色方块和连线，节点文本来自规则树的命名节点：

```text
[动词连用形] → [て／で形] → [补助动词：しまう] → [输出：动词循环类]
```

迁移顺序：先完成六类实体和规则 schema；再将 te*\* 和 contracted_te*\* 从复合词条迁移为补助规则，缩约形式作为同一规则的 surface_variant；随后由规则元数据选择单一专用执行器，并逐类建立输入许可、状态输出、顺序处理和停机策略；词性转换须继续接入目标活用表，例如“読み＋たい → イ形容词性 → たく／たかった”；最后合并查询路由、气泡展示和词条资源。

验收重点：読んでしまう只产生一个补助构式命中并链接到“しまう”；読んでしまった能继续接时态层；読ませられている按顺序形成使役被动与补助层；だけ／は保持前项状态；文语ごとき与现代ようだ分开。
