# 查词与阅读投影问题追踪

记录日期：2026-10-14。本文依据当前 CLI 分析、GiNZA BERT large CUDA 实测、本机三套词典查询和阅读器投影代码登记用户反馈。复现输入使用 `target-lookup-review/debug/readux-nlp.exe` 的 `stdio` 接口；分析结果与词典结果分开判断。

## 判断口径

“查询对象”指后端 `LookupTarget`；“胶囊”指前端 `readerCapsuleRanges` 及其后续文本分段生成的显示范围。两者来源不同，修复时需要分别验收。`accepted` 只表示当前候选经过词典索引命中，不能证明整体范围、词性或层级符合用户预期。

状态含义：

- **可直接修复**：现有数据已经包含所需信息，调整规则或投影即可验证。
- **需要词典/资源验证**：代码可以提供候选，但默认结果依赖词典条目、词性或来源数据。
- **需要重新设计**：当前协议没有保存区分问题所需的原始证据，需先扩展对象或查询接口。
- **输入能力限制**：需要修改文本准备、分词或用户选择模型，不能只在气泡显示层解决。

## 代码与数据依据

2026-10-15 补充：`立ち回れない` 的 UniDic 词元为 `立ち回る`，基本表记为 `立ち回れる`，当前词形为 `立ち回れ`。查询与活用推导采用词元对应的原型表记；可能动词基本表记、下一段活用字段及来源证据继续保留。识别同时要求下一段活用和五段词尾到 e 段＋る的对应关系，可按基本表记或词元读法确认。读法确认时原型沿用基本表记的汉字和假名，如 UniDic 的 `帰れる` 词元为 `返る`，查询原型仍为 `帰る`。同类的 `読む／読める`、`書く／書ける` 等采用相同规则，`食べる`、`見える`、`聞こえる` 等独立动词保持原有查询原型。正式分析和首选词典条目的回归入口为 `scripts/test_reader_morphology.py`；两个气泡均显示 `立ち回る → 立ち回れ（る→れ）`。

- 查询候选、功能成员排除、连续组合、作者注音候选和外层贪心覆盖集中在 [`crates/readux-core/src/dictionary/targets.rs`](../crates/readux-core/src/dictionary/targets.rs) 的 `build_profiled`、`projected_core_indices` 和 `target`。
- 胶囊范围由 [`src/reader/lookupPresentation.ts`](../src/reader/lookupPresentation.ts) 的 `readerCapsuleRanges` 独立生成，文本分段在 `ReaderDocumentView.vue` 的 `capsulesForParts` 再次切分。
- 活用连接和 operator 范围由 [`crates/readux-nlp/src/morphology_machine.rs`](../crates/readux-nlp/src/morphology_machine.rs) 生成；整体词形拼接由 [`crates/readux-nlp/src/formation.rs`](../crates/readux-nlp/src/formation.rs) 的 `attach_words` 完成。
- 注音清洗和范围扩展分别位于 [`crates/readux-nlp/src/prepare.rs`](../crates/readux-nlp/src/prepare.rs) 的 `prepare_text`/`grouped_annotations` 与 [`crates/readux-nlp/src/ruby.rs`](../crates/readux-nlp/src/ruby.rs) 的 `validate_ruby`。
- 现有复现脚本输出了上述样例的 token、lemma、reading、query forms、morphology chains、outer/inner/pending targets；关键结果包括：`滑り込む` 一个 outer target、`体育座り` 一个 outer target、`もうじき` 被拆为 `もう` 与 `じき`、`ちょこんと` 被拆为 `ちょこん` 与 `と`、`なら` 没有 outer target。

## BERT 与词典实测补充

- 昨日的 CUDA 实验基线见[GiNZA CUDA 测量](ginza_cuda_measurement.md)，日期为 2026-10-13；其中记录 RTX 3050 Laptop GPU、PyTorch `2.7.1+cu128`、CUDA 可用及 `ja-ginza-bert-large 5.3.0`。本次复用 `experiments/ginza-cuda/Scripts/python.exe` 与 `scripts/benchmark_ginza_optimized.py`，FP16 实测确认 `torch.cuda.is_available()` 为 `True`，两条例句共 16 token，重复输出一致，峰值分配约 659 MiB。
- BERT 原始输出保存在 `.agents/analysis/bert-target-output.json`；输出显示 `かくして` 在独立句与上下文句中均为 `かく` ADV、`し` VERB（lemma `する`，连用形）、`て` SCONJ。应用服务的 token 与目标复现保存在 `.agents/analysis/kakushite-lookup-targets.json`，整体范围未生成 `かくして` 目标。
- `.agents/analysis/lookup-dictionary-audit.jsonl` 由本机正式查词服务查询三套数据库，词条均为精确表记命中结果。`かくして` 命中三省堂与小学馆，`もうじき`、`じゃなくて`、完整示例 `的にだっけ` 未命中；`ちょこんと`、`びりっと`、`ひとつ`、`ふたつ`、`なら` 均有相应词条。占位符 `○○` 未提供实际词干，`しい` 后缀命中不能替代完整表达验证。
- L08 自拟样例的 token、查询目标和词典结果保存在 `.agents/analysis/l08-composed-case-audit.json`；15 个「しい」词例的对照结果保存在 `.agents/analysis/l08-suffix-cases.json`。前三个「的にだっけ」样例均未生成完整范围目标，15 个「しい」样例均生成完整 token 范围。

## 建议实施顺序

1. 先统一后端 `LookupTarget` 与前端 capsule 的身份和范围，补充未命中分析证据；这会同时解决 L02、L10、L13、L17 的可见性问题。
2. 再修正查询键与显示字段：接辞标记、平假名显示、词典 canonical form 和注音候选范围，覆盖 L05、L06、L07、L12。
3. 最后增加有限的表达/数量/变体规则，并扩展选择范围映射，覆盖 L08、L09、L11、L14、L15、L16；每条规则保留原始 token 和可追溯的规范形式。
