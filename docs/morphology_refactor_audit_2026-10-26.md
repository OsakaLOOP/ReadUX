# 活用链重构审计记录（2026-10-26）

## 结论

当前工作已经形成可运行的重构基础，但整体重构尚未完成。按用户提出的完成标准衡量，当前约完成 48%：底层状态、规则元数据、判断类第一批正式 concept、补助动词资源拆分、阶段约束和回归接入已经达到可继续开发的程度；规则全集迁移、六类执行语义的完全分离、词性转换的连续活用、文言规则、补助动词全覆盖和动态规则树仍未完成。

45%描述的是面向最终目标的整体完成度。若只看基础架构，约有 65% 已经成立；若只看语法规则和旧词条迁移，约有 30%～35% 已经成立。当前结果可以支撑下一阶段开发，不能作为“重构已经收束”的依据。

## 已经成立的部分

### 资源归属和 て 边界

ている、てしまう、ておく等形式已经从补助词条资源中拆出构式规则，いる、しまう、おく、ある、いく、ゆく等作为补助动词本体保存。te_connection 作为独立连接规则存在，补助词规则通过连接器引用它。运行时和搜索入口已经优先指向补助动词本体，読んでいる、読んでしまう、読んでおく、読んでゆく等代表形式可以形成父链和子链。

当前仍有一项与用户“直接删除”要求不完全一致：旧的 grammar.aspect.te_iru 等构式概念在 grammar source 中仍以 deprecated 形式保留，供历史重定向和旧缓存兼容。活跃目录和搜索索引已经隐藏这些入口，但仓库源数据尚未完成最终删除。若按字面执行“重复的 て 开头词条必须直接删”，最终应将历史 ID 映射移入单独的迁移文件，再从正式 concept source 和 catalog redirect 中删除旧构式实体。

### 六大类的基础契约

六大类已经在配置和文档中固定为：动词循环类、イ形容词转换类、ナ形容词判断类、文言活用类、补助动词类、插入语类。阶段、执行器、排序和停机方式作为规则属性保存，没有反向污染实体分类，这一点符合设计要求。

MorphologyState 已记录词性、活用形、活用类型、活用形式和实体类别；operator metadata 已覆盖现有 108 个活用 operator，并包含输入类别、输出类别、executor、stage、terminal mode、排序值、allowed_after 和 same_layer 等字段。MorphologyChain 已保存 terminal 状态、父链关系、来源证据、诊断和候选状态。

### 顺序约束和停机状态

状态机已经采用以下阶段顺序作为约束基础：

voice → te_support → desire → polarity_politeness → tense → modality → boundary

规则可以声明 allowed_after 和 same_layer，逆序组合会生成 rule_order_conflict 并降为 candidate。停机状态已经进入链结果，可以区分继续接续、句末或中顿相关状态。这个部分已经从单纯的词条匹配进入规则约束层，但仍缺少全量规则的严格顺序表和组合验收。

### 补助动词的第一层递归

补助执行器已经验证连接器、建立父子链、保留补助动词本体、检查连续字符范围并记录 GiNZA 关系证据。て后插入 は／も 的路径能够回溯到原连接器，再接补助动词。补助深度也有配置上限和诊断。

这已经证明补助动词可以作为独立的可递归实体运行，尚未覆盖所有连用形补助和补助词自身的连续活用。

### 插入语范围的收紧

普通格助词和一般接续助词不再因为“助詞”这一大类自动进入插入语。は／も／だけ／さえ／こそ／など／とか等指定成分才进入插入规则，て／で保持连接器身份。名词化和 のだ 仍需要在规则迁移中继续拆分语义。

### 规则树的可读性原型

规则树已经有命名节点、摘要、代表输入、输出和有限分支，前端对分支数量进行了截断，展示层不会直接穷举 UniDic 条件。动词循环类和补助动词类的分支已经能按“未然形输入”“连用形入口”“て形接续”“连用形补助”等语义层级阅读，符合用户要求的树形表达方向。

## 尚未成立的部分

### 六类还没有形成同等完整的运行时模型

代码中已经存在多个 executor 入口，但实际状态推进仍以统一的 Transition::Core、Attach、Support、Insert、Boundary 路径为主体。各 executor 在转移之后修改整体状态，尚未完全成为各自拥有输入判定、接续许可、输出转换、递归策略和停机策略的独立执行单元。

当前成立程度如下：

| 类别 | 当前成立程度 | 主要缺口 |
| --- | --- | --- |
| 动词循环类 | 中等 | 仍依赖通用 Attach 路径；使役、被动、可能、否定、礼貌、时态的完整有限状态表未完成 |
| イ形容词转换类 | 初步 | たい、ない能切换整体类别，但 たくない、たかった、なかった等连续活用尚未形成完整链 |
| ナ形容词判断类 | 初步 | そうだ、ようだ、みたいだ、らしい、べきだ、はずだ的词干和 だ／だった／で／な 收尾未逐项完成 |
| 文言活用类 | 很初步 | 当前文言活用表只有 ごとし 初始项，ク活用、シク活用、ナリ活用、タリ活用及 ず／ぬ／べし 尚未完成 |
| 补助动词类 | 中等偏初步 | て／で递归已成立；连用形补助、たり、补助词自身活用和全量顺序组合未完成 |
| 插入语类 | 较完整 | 白名单和状态保持已成立；动态父链投影、名词化和 のだ 的语义边界仍需拆开 |

因此，当前可以说“六类契约已经建立，部分执行器已经接入”，不能说“六类执行模型已经全部完成”。

### 规则树仍是静态摘要，不是实际命中树

当前配置中的规则树已经加入イ形容词转换类、ナ形容词判断类和文言活用类，六大类根节点已经齐全；树仍然是静态摘要，尚未根据真实命中链动态投影前接形、父子链、跳过阶段、停机状态和顺序冲突。

此外，展示树还没有从真实命中链动态投影以下内容：实际前接活用形、命中的规则组、跳过的阶段、插入语节点、真实父子链、停机状态和顺序冲突。当前树可以解释“某类规则大致如何运行”，还不能解释“这一个句子为什么得到当前识别结果”。

最终规则树应当以六大类为固定根节点，每个根节点下只显示两到三组命名分支，例如“未然形输入”“连用形补助”“判断词干收尾”“文语活用表”“范围保持”。完整条件应留在节点详情中，由实际命中链提供证据；展示树本身继续保持聚类后的可读规模。

### 词性转换还没有贯穿后续活用

当前执行器能够将前项整体标为形容词或形状词，但后续 operator 仍有相当部分沿用旧的通用附加逻辑。用户要求的关键语义是“前项和本词合成整体后，整体词性和活用形改变”，这需要在后续每一步继续读取转换后的状态。

至少需要完成以下状态链并逐条断言：

読む（动词连用形）＋たい → たい（イ形容词性）
たい＋ない → たくない
たい＋た → たかった
読む（动词未然形）＋ない → ない（イ形容词性）
ない＋た → なかった

やすい／にくい／づらい也应按照同一转换模型接入，而不是继续作为互不相关的词条附加。

### 补助动词的覆盖范围还不完整

目前补助构式资源已覆盖第一批 て 连接形式，但以下规则尚未统一进入同一个可递归模型：

始める、続ける、終わる、出す、すぎる、直す、切る、かける、まくる、かねる、そこなう、そびれる、とおす、ぬく、つくす、あう。

这些形式存在连用形直接接续、语义范围不同、终止和中顿行为不同等差异。执行器需要以连接器类型和规则条件区分，而不是用一个“补助动词”标签覆盖全部形式。

### 正式 grammar concept 和 morphology.chain 迁移未完成

仓库中仍有大量 operator 使用通用的 morphology.chain 概念。高频未迁移组包括 そうだ、ようだ、みたいだ、らしい、はずだ、べきだ、条件接续、禁止、程度、完成、未然和连用补助等。它们需要分别建立 concept、sense、解释、接续条件、代表例句、反例和规则引用。

当前 teConstructions.json 的 entries 与 rules 已完成资源拆分，但 rules 仍主要以 kind 和 component 关联本体，正式 grammar concept 的逐规则引用和统一 sense 关系还需要补全。

### 文言规则只有入口，没有完整表

文言 executor 已进入运行路径，但 classical_forms 目前只有一个初始表项。文言规则必须独立维护活用型和接续表，至少覆盖ク活用、シク活用、ナリ活用、タリ活用、べし、ず／ぬ、ごとし／ごとき，并明确现代 ようだ 与文言形式的边界。

## 当前自洽程度

当前架构可以分成三个层面判断：

1. **结构层：约 65%～70% 自洽。** 状态、metadata、阶段、停机、补助父子链、插入白名单和资源拆分已经使用同一套方向；代码和配置之间仍有通用 transition 与专用 executor 并存的问题。
2. **语义层：约 35%～40% 自洽。** 代表规则能解释，完整活用链和词性转换链还不能覆盖用户提出的主要类型；文言、判断、连续形容词活用和连用补助缺口明显。
3. **展示与词条层：约 40%～45% 自洽。** 接续条件区域和有限分支树已经具备原型，六类根节点、动态命中树、词条概念统一和旧 て 源实体清理尚未完成。

综合后得到约 45% 的整体完成度。这个判断与当前测试通过并不矛盾：现有测试证明已接入的案例可以运行，不能证明规则全集和新架构契约已经完成。

## 收束条件

重构可以宣布完成，需要同时满足以下条件：

1. 规则树固定展示六大类根节点，每类有命名分支和两到三条代表输入；实际命中时可以投影真实链，完整条件进入详情层。
2. 六类 executor 都有独立的输入许可、输出转换、顺序处理、递归或有限循环和停机逻辑；通用 transition 只负责调度，不承担类别语义。
3. 所有词性转换都能继续活用，至少覆盖 たい／ない 的否定、过去、连用和中顿组合。
4. 补助动词本体、て 连接器和补助规则完全分离；所有 て 开头的重复正式词条从 source、catalog、search index 和前端入口删除。历史兼容 ID 若保留，必须位于独立迁移映射中，不再是 grammar concept。
5. morphology.chain 中的规则逐项迁移到正式 concept，并为每条规则补充接续条件、正例、边界或反例、词性变化和停机方式。
6. 文言活用表和现代判断结构分别完成，至少覆盖设计中列出的基本活用类型。
7. 连用形补助和 て／で 补助共用递归框架，但连接器条件、语义说明和停机行为分别定义。
8. 旧词条覆盖清单中的每一项都有新规则或新词条归属，并留下可复核的输入状态、输出状态、规则阶段、证据和术语说明。
9. 模块文档、术语对照、代表例句和规则树展示同步更新，最终运行 Rust、UI、catalog、构建和规则树审计。

## 当前阶段应采用的判断

当前成果适合继续进行逐类、逐词条的重构开发，基础方向已经正确，尚未达到可以交付为“全面完成”的程度。下一阶段的主要工作应集中在正式 concept 迁移、六类规则树补全、词性转换后续活用、文言表和连用形补助覆盖；继续增加资源数量而不先完成这些语义闭环，会扩大配置规模，却不会提高整体自洽性。
