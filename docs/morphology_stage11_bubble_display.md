# 活用词条气泡与接续方式展示设计

本文将执行计划第 11 阶段的界面约定、词条内容和接续规则投影整理为后续接入规范。文中例句用于说明展示和规则设计；每条路径是否已经由运行时支持，仍以配置及验收结果为准。

## 一、设计边界

现有活用词条气泡保持当前职责，继续显示活用类别、词条解释和例句。新增独立的接续方式气泡，按空间堆叠在现有活用词条气泡上方或下方。词典查询气泡、活用词条气泡和接续方式气泡各自保持当前用途。

新气泡包含两类投影：

1. **补助动词递归关系**：按本句实际父子链展示补助词如何逐层接入。
2. **当前词条的前接方式**：调用该用法所引用的识别规则，显示前项词类、活用形、必要的词形变化及连接形式。

普通规则只回看声明所需的前项，通常为一项。规则明确依赖更长的连续上下文时，按规则显示相应的前两项或更多项，例如「动词未然形＋ず＋に」。界面不为所有规则统一增加多项回溯。

只有一条标准前接路径时采用线性接续。存在多种前项词类、不同变形路径或更长的上下文条件时，采用分支。前项词类、接续形式和当前词条始终可见；词类内部的活用型和具体变化可折叠。

## 二、活用词条气泡内容

活用词条气泡回答“当前词条是什么、这里使用哪个用法、该用法表达什么”。接续条件由新气泡展示。

| 内容     | 初稿约定                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 词条名   | 显示词条本体，如「いる」「たい」「ない」。构式名「ている」作为本句形式或副标题出现，词条名仍为「いる」。 |
| 词类身份 | 显示助动词、补助动词、接续助词、插入成分、文言助动词等身份。                                             |
| 词条用法 | 显示愿望、否定、进行／状态持续、完成／遗憾、变化等词条标明的语法功能。                                   |
| 本句形式 | 显示当前命中的词形或构式，例如「いた」「読んでいる」。                                                   |
| 简要说明 | 用一至两句说明功能和主要语义，不重复前接条件。                                                           |
| 例句     | 优先显示一至两条例句及简短译文，例句应体现当前用法。                                                     |
| 识别状态 | 仅在候选或存在诊断时显示轻量状态标记；具体诊断放入详情。                                                 |

词类身份、语法功能、词形现象和识别状态分别呈现。撥音便、イ音便和缩略形式等词形标签只在当前词形存在对应识别证据时显示。阶段、执行器、内部规则 ID 等字段留在分析数据或诊断详情中。

词条正文沿用 grammar source 和编译后的 grammar catalog。补助动词词条本体与构式规则分开管理：「いる」承载补助用法说明，「ている」由共享连接规则和「いる」词条共同表达。

## 三、接续方式气泡

### 补助动词递归关系

递归图的节点对应实际父子链，显示词条本体和本句词形；连线显示连接形式和活用步骤。父子关系读取分析产物中的链关系，不根据词面重新判断。

```text
読む
└─ て形：読んで
   └─ 补助动词「しまう」
      └─ て形：しまって
         └─ 补助动词「いる」
            └─ 过去：いた
```

存在补助父子链时显示递归关系；没有补助链时收起该区域。当前词条的前接方式单独展示，避免和递归关系混成一棵含义不清的树。

### 当前词条的前接方式

前接图从实际规则声明生成。唯一的标准路径采用线性方式：

```text
［动词］─［连用形：読み］─＞【愿望助动词 たい】
```

多条路径或特殊变形采用分支。「ずに」需要回看「ず」之前的前项：

```text
［动词］──［未然形：行か］────┐
                                ├─＞【否定助动词 ず】─＞【に】
［形容词］─［未然形：高から］──┘
```

规则只声明直接前项时显示一项。对「ずに」等明确声明多项依赖的规则，显示其实际需要的上下文。识别结果负责定位本句命中的分支；未命中的已配置分支仍可查看。前端不推测未声明或未识别的路径。

### 共用的て／で连接规则

「て／で」接续树属于连接形式自身的共享规则。补助动词用法通过规则引用使用该树；「いる」「しまう」「おく」等条目不各自保存一份接续分支。

此树的前项词类、「て／で」连接形式和当前补助动词节点保持可见。动词、形容词、名词等词类入口不可折叠；入口内部具体活用类别及变化方式可以折叠。识别命中的细分路径默认展开，其他细分路径收起。连接形式和当前词条节点不可折叠。

```text
［一段动词］────────［连用形：去る］──────────┐
［カ变动词］─────────［连用形：き］───────────┤
［サ变动词］─────────［连用形：し］───────────┤
［五段动词］─────────［连用形及音便］─────────┼─＞【接续助词 て】─┐
［被动／使役助动词］──［连用形：去る］─────────┤                    │
［イ形容词］─────────［连用形：词尾变く］──────┤                    ├─＞【补助动词 いる】
［愿望助动词 たい］───［连用形：たく］──────────┘                    │
                                                                         │
［五段动词］─────────［拨音便等］──────────────┐                    │
［动词否定］─────────［未然形＋ない］──────────┤                    │
［イ形容词否定］──────［连用形＋ない］──────────┤─＞【接续助词 で】─┘
［ナ形容词／名词否定］─［词干／名词＋でない］────┤
［ナ形容词］─────────［连用形］────────────────┤
［名词］─────────────［断定词尾的连用形式］─────┘
```

此图规定界面层级和折叠方式。各条前接路径是否进入正式规则集合，须逐项核对现有配置、运行结果和专项验收。

### 命中、折叠和诊断

- 主词类、连接形式、当前词条始终显示。
- 主词类内部活用型和具体词形变化可折叠；命中路径默认展开并高亮。
- 已识别路径按正常状态显示；候选路径保留命中线索并标明候选。
- 诊断说明本次分析为何处于候选状态，不改变规则图。
- 只有配置声明了多项依赖的规则才显示更长的上下文。

## 四、代表性显示稿

### 例一：読んでいる

```text
现有活用词条气泡
いる
补助动词 · 进行／状态持续
本句形式：読んでいる

在动词て形后表示动作持续，或动作结果形成的状态。

庭で花を育てている。
在庭院里种着花。
```

```text
新增接续方式气泡
补助动词递归关系
読む
└─ て形：読んで
   └─ いる：いる

前接规则：て／で
动词
└─ 五段动词（本句命中）
   └─ 连用形・拨音便：読ん
      └─ 接续助词「で」
         └─ 补助动词「いる」

形容词、名词等词类入口保持可见；各入口内部的细分变化可折叠。
```

### 例二：読みたい

```text
现有活用词条气泡
たい
助动词 · 愿望
本句形式：読みたい

表示说话人或询问对象想进行前项动作的愿望。「たい」本身按形容词型活用。

熱いお茶を飲みたい。
想喝热茶。
```

```text
新增接续方式气泡
［动词］─［连用形：読み］─＞【愿望助动词 たい】
```

### 例三：行かずに／高からずに

```text
［动词］──［未然形：行か］────┐
                                ├─＞【否定助动词 ず】─＞【に】
［形容词］─［未然形：高から］──┘
```

「行かずに」用于动词路径验收；「高からずに」用于形容词分支的规则设计和覆盖核对。示例说明设计目标，不表示形容词分支已经接入运行时识别。

## 五、规则内容和数据来源

| 展示内容                                 | 数据来源                                                                     | 用途                         |
| ---------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------- |
| 词条名、词类身份、释义和例句             | grammar source、grammar catalog                                              | 现有活用词条气泡             |
| 规则名称、输入类别、输入形和输出状态     | morphology.json 中的 operators、rule_metadata、connections、sequences、forms | 生成前接路径                 |
| 词类内部变化标签、连接形式和折叠分组     | morphology.json 中连接规则及 presentation；缺少名称时补充同源展示元数据      | 生成共享树和细分节点         |
| 本句表记、命中范围、父子关系、状态和证据 | Rust morphology artifact                                                     | 定位分支、展示当前路径和诊断 |

前端消费分析结果和规则配置，不重新实现接续判定。全局 rule_tree 用于说明六类实体的总览；单条词条的接续方式读取具体连接规则和连续规则。

历史构式标识继续通过迁移映射兼容。正式词条和查询身份指向「いる」「しまう」等本体；补助条目通过 connector 引用共享接续规则。展示元数据可以补充名称、顺序和折叠分组，不复制运行时接续条件。

## 六、额外识别规则设计清单

每个词条按具体用法逐项确认：

1. 词条本体、词类身份和语法功能。
2. 每条路径允许的前项词类和活用形；规则确实依赖时再限定活用型或词形。
3. 接续是否只有一条标准路径，是否存在不同变形，是否需要回溯两项以上。
4. 连接形式由当前用法拥有，还是引用共享连接规则。
5. 每条路径的正例、相邻边界、输出状态、命中范围和词条归属。
6. 候选、冲突和未覆盖路径如何标记。

建议优先核对以下多路径用法：

| 用法                       | 前接路径                                                     | 设计重点                                 |
| -------------------------- | ------------------------------------------------------------ | ---------------------------------------- |
| 否定「ない」               | 动词未然形；イ形容词连用形（く）；ナ形容词／名词经「で」接续 | 显示不同词类和变形，说明否定成分归属     |
| 文言否定「ずに」           | 动词未然形＋ず＋に；形容词未然形「から」＋ず＋に             | 明确两项上下文，单独核验形容词路径       |
| 过去「た／だ」             | 动词连用形及音便；イ形容词「く」变化；断定结构「だった」     | 分开表示前项形式、词尾变化和接续来源     |
| 判断收尾「だ／で／な／に」 | 名词或形状词前项及判断结构的不同收尾                         | 区分词条身份、连接形式和输出状态         |
| 缩约补助形式               | ている、てしまう、ておく的缩约、浊化和后续活用               | 复用共享连接规则，保留实际词面和本体身份 |

此表提供后续规则工作入口。每个分支进入正式展示前须在配置中声明并由运行结果核验；没有规则依据的分支留作待办。

## 七、接入顺序与验收

### 接入顺序

1. 建立词条、concept、operator、连接规则和历史迁移标识的对应关系。
2. 为现有活用词条气泡提供统一内容投影，保持词典查询和活用说明行为。
3. 从 Rust artifact 与规则配置生成补助递归关系、前接路径、命中状态和诊断。
4. 新增独立接续方式气泡，接入现有悬浮、关闭延迟和定位流程；按空间选择堆叠方向。
5. 按规则逐项接入共享连接树、多路径规则、折叠状态和当前命中高亮。
6. 使用真实和合成分析样例核验正文悬浮、词条内容、两种图示和词典查询完整流程。

### 验收条件

- 现有词典气泡与活用词条气泡的查询、内容和交互保持正常。
- 新气泡作为独立面板与活用词条气泡堆叠，并按可用空间选择上下位置。
- 补助递归图与 parent chain、连接形式、词条本体和本句词形一致。
- て／で细分路径来自共享连接规则；补助词通过规则引用复用该树。
- 唯一路径线性显示；多路径和专门变形按声明显示分支。
- 主词类、连接形式和当前词条不可折叠；词类内部细分按约定折叠。
- 当前命中分支由分析产物定位；候选状态和诊断由识别结果提供。
- 两项或更多项上下文只用于明确声明此类依赖的规则。
- 词条释义不重复接续条件，接续图不复制词条正文。
