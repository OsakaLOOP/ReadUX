# 活用词条气泡与接续方式展示设计

本文定义执行计划第 11 阶段的界面约定、词条内容和接续规则投影。已审计的接续路径与谓语身份、接续标签审阅共同作为扩展依据；实际覆盖范围以配置及验收结果为准。

## 当前界面约定

词条面板表头左侧显示语法名称与词条本体，右侧第一行显示词性与当前活用形，第二行显示词形变化，表头下方设分隔线。词干和紧接词干的首个活用显示完整变化，后续成分显示局部变化。接续面板与词条面板始终位于正文同侧，活用面板靠近正文，接续面板位于外侧。面板宽度按图示内容计算，高度随内容及动画变化；滚动操作保留，滚动条隐藏。

词干活用表头左侧首行采用词性与活用类别，如「動詞・五段活用」，第二行显示实际词形「読み」；右侧首行显示「連用形」，第二行显示「読む → 読み」。其他活用类别采用相同布局。

局部变化依据前后词形与链内成分范围统一选取：词形变化时保留发生变化的完整成分，纯追加时保留上一个完整成分。例如「いる→いた」「いく→いくこと」「こと→ことに」「と→とする」。范围投影适用于全部活用类型及新增规则。独立连接器已归入前项，后项词形仅由自身成员生成；「作ろうと＋する」显示「作ろうとする」。

元素的活用信息按学校文法表达接续下一项时采用的实际活用形，包括未然形、连用形、终止形、连体形、假定形、命令形和文言已然形。无活用成分显示“无活用”，缩略和音便附在对应元素后。复合规则逐个读取成员词形，表头采用条目末尾成员的活用形。

「かもしれない」在句中接续图中作为完整节点展示，保留整体原型与实际词形，如「かもしれない → かもしれなく」；活用信息读取末尾「ない」。后续「なる」及其补助链继续按所属层展示。

箭头按具体接续功能命名。判断词尾保留前项类别：「学生です」显示名词谓语（敬体）与判断，「学生だ」显示名词谓语（简体）与判断，「綺麗だ」显示形容动词与判断。推量、条件、名词化、连体修饰、连用修饰、补助与文言活用采用相应功能名称；明确的派生变化可显示词性转换。后端保留前项词汇类别及词尾实际活用信息，名词谓语沿判断词尾接续表继续处理。

前接图保留 D3 的树形布局。各父节点在直属子节点的实际范围内居中，范围从首个分类顶部到末个分类标题底部；中间分类展开的列表计入布局，末个分类列表保留显示且不参与父节点居中。当前路径连线最后绘制，所属分类持续高亮，命中节点使用淡背景。

句中关系覆盖完整父子链，使用实际分段词形。节点内部固定两行：首行显示功能标签及词形，必要时用“原形 → 实际词形”表达变形过程；第二行显示活用、音便和缩略信息。中文标签、日文词形分别采用界面字体与日文字体。每个补助层从其连接器之前折行，如「に＋なる」「て＋いく」；直接接续与缩约补助从本体之前折行，后续没有补助的纯接续形保留在原行。使役、被动、愿望、极性、礼貌、时态及一般词性变化连续排列。认识、推量、传闻单元直接承接使役被动、极性、礼貌、时态或补助层时折行一次；该单元内部的判断、修饰、推量等成分连续排列。原因「から」、连用修饰「に」及插入成分沿所属单元排列。每一行均从左向右连接，全部垂直连接显示箭头。词性标题的边框高亮由标题自身的悬浮或聚焦触发，列表项的命中状态与悬浮状态分别呈现。

句中关系的逻辑横坐标从 1 开始，同一行每增加一个元素加 1。折行时，横坐标达到 2 则减 1，折行连线呈 45° 左下方向；横坐标小于 2 时上下居中对齐。折行仍由上述语法边界决定。普通折行的节点间距为 26 px，斜向折行为两倍，即 52 px；斜向折行的水平位移同为 52 px。元素宽度按内容计算。

折行箭头的标签以连线中点为定位基准，文字与连线保留右侧 9 px 的间距，位置随节点动画同步更新。

句中关系与前接规则图根据当前活用选择自动横向定位。单个或多个命中元素按完整联合范围居中显示；联合宽度超出可视区域时，图示等比例缩放并保留两侧间距。初次显示、选择变化、展开动画和面板宽度变化时同步更新定位，布局稳定后保留手动横向滚动。

前接规则使用横向树，て、で分别为一级分支。全部词性节点始终显示，同一气泡内宽度统一并保持稳定。展开图标和计数位于节点左侧，标题保持居中；同一时间仅允许一个类别展开，当前命中路径始终显示。存在尚未显示的条目时提供展开入口，包含一条路径的类别同样适用；唯一条目已作为当前路径完整显示时省略展开控件。细分类采用无外围方框的列表，词性节点向下伸出悬挂竖线，再以短横线连接列表各项。图中仅当前路径的连接和列表引导线显示高亮箭头。以下示意图用于说明语言关系，实际界面采用本节的布局约定。

## 一、设计边界

词典、活用词条和接续方式三个面板已按当前界面约定接入。活用词条面板显示词类、实际活用形、词形变化、释义及例句；接续面板显示句中关系和接续规则。面板位置、尺寸、折叠和高亮沿用已审阅的界面。

接续面板包含两类投影：

1. **补助动词递归关系**：按本句实际父子链展示补助词如何逐层接入。
2. **当前词条的前接方式**：调用该用法所引用的识别规则，显示前项词类、活用形、必要的词形变化及连接形式。

规则读取声明所需的输入状态和连续语素。连接器接续保留“前项→连接器→后项”的两级依赖；「ずに」等连续词尾另行记录条目内部成员。前项依赖、条目成员和分词恢复范围分别维护。

只有一条标准前接路径时采用线性接续。存在多种前项词类、不同变形路径或更长的上下文条件时，采用分支。前项词类、接续形式和当前词条始终可见；词类内部的活用型和具体变化可折叠。

## 二、活用词条气泡内容

活用词条气泡回答“当前词条是什么、这里使用哪个用法、该用法表达什么”。接续条件由新气泡展示。

| 内容     | 初稿约定                                                                                                 |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 词条名   | 显示词条本体，如「いる」「たい」「ない」。构式名「ている」作为本句形式或副标题出现，词条名仍为「いる」。 |
| 词类身份 | 显示助动词、补助动词、接续助词、插入成分、文言助动词等身份。                                             |
| 词条用法 | 显示愿望、否定、进行／状态持续、完成／遗憾、变化等词条标明的语法功能。                                   |
| 本句形式 | 显示当前命中的词形或构式，例如「いた」「読んでいる」。                                                   |
| 简要说明 | 用一至两句说明功能和主要语义，不重复前接条件。                                                           |
| 例句     | 优先显示一至两条例句及简短译文，例句应体现当前用法。                                                     |
| 识别状态 | 仅在候选或存在诊断时显示轻量状态标记；具体诊断放入详情。                                                 |

词类身份、语法功能、词形现象和识别状态分别呈现。撥音便、イ音便和缩略形式等词形标签只在当前词形存在对应识别证据时显示。阶段、执行器、内部规则 ID 等字段留在分析数据或诊断详情中。

词条正文沿用 grammar source 和编译后的 grammar catalog。补助动词词条本体与构式规则分开管理：「いる」承载补助用法说明，「ている」由共享连接规则和「いる」词条共同表达。

## 三、接续方式气泡

### 补助动词递归关系

递归图的节点对应实际父子链，显示词条本体和本句词形；连线显示连接形式和活用步骤。父子关系读取分析产物中的链关系，不根据词面重新判断。

```text
読む
└─ て形：読んで
   └─ 补助动词「しまう」
      └─ て形：しまって
         └─ 补助动词「いる」
            └─ 过去：いた
```

句中关系始终采用实际链成员；存在补助父子链时递归显示。当前词条的前接规则在独立区域呈现。

### 当前词条的前接方式

接续分类分别记录前项词类、路径分支和依赖结构。词类入口使用动词、イ形容词、ナ形容词、名词、助动词和文言用言；既有的否定、判断、列举等功能分组保留相应接续身份。活用型与具体词形作为细分类。名词与代词可共用名词入口，判断词尾之后保留原谓语类别。新增路径使用 exact_category 明确区分词类；既有判断兼容路径沿用名词谓语共享判断接续表的规则。

依赖结构在 connection_types 中分为直接接续、连接器接续、连续词尾、谓语构式、词内活用和插入成分。直接接续读取当前输入状态；连接器接续同时依赖连接器之前的用言及连接器本身，如「読ん＋で＋おく」「意向形＋と＋する」「名词＋に＋なる」「连用形＋たり＋する」。连续词尾完整识别自身成员，如「ず＋に」「ませ＋ん」；成员数量与前项数量分别记录。谓语构式连接前项条件和完成自身活用的后项谓语，如「なければ＋ならない」。词内活用依据当前 token 自身的活用证据生成说明。

路径数量由合法输入决定，前项依赖由结构决定。共享连接器仍属于复合依赖；引用共享规则时须保留连接器及其输入依据。「ておく」具有“用言→て／で→おく”的依赖，三个缩约补助形式保留同一展开关系，并采用实际分词定位范围。可选插入项按所属链保存，语素回看数量依据命中结果计算。

| 结构分类 | 判定依据 | 成员与前项范围 |
| --- | --- | --- |
| direct：直接接续 | 后项直接采用前项状态 | 额外语素条件由路径的 predecessors 明确声明；如判断否定分支同时核对前项和で |
| connector：连接器接续 | 前项形式、连接器、后项身份共同成立 | 包括全部て形补助、三个缩约补助、意向形＋と＋する、たり＋する／できる、に＋なる及判断で＋ある |
| sequence：连续词尾 | 一个连续规则识别条目内部成员 | 「ませ＋ん」「ず＋に」等成员位于词条范围内；よう／はず等同时保留各自直接路径 |
| predicate：谓语构式 | 前项条件形式与后项谓语共同成立 | 九种义务和三种禁止构式保留前项条件、后项身份及必要的否定证据 |
| inflection：词内活用 | 依据本身活用形生成说明 | 独立词尾分析时继续采用相应前接状态；前项与自身范围分别定位 |
| insertion：插入成分 | 所属位置、词法身份及需要的连接证据共同成立 | 保留前项状态，实际成员继续归属原链 |

connection_types 记录条目涵盖的主要结构；具体路径和本次成员范围共同说明当前接续。该分类独立于六类实体及执行器分类。

连接器接续共 30 项。て形补助的 22 项为「ていい、ている、てある、てしまう、ておく、ていく、てゆく、てくる、てみる、てくださる、てもらう、ていただく、てかかる、てあげる、てくれる、てやる、てほしい、てごらん、てみせる、てたまらない、てならない、てやまない」；三个缩约条目分别对应ている、てしまう、ておく；其余五项为「ようとする、になる、たりする、たりできる、である」。各项均有前项形式与连接器的共同要求。

前接图从实际规则声明生成。唯一的标准路径采用线性方式：

```text
［动词］─［连用形：読み］─＞【愿望助动词 たい】
```

多条路径或特殊变形采用分支。「ずに」整体条目读取「ず」之前的输入状态，条目内分别保留「ず」「に」：

```text
［动词］──［未然形：行か］────┐
                                ├─＞【否定助动词 ず】─＞【に】
［形容词］─［未然形：高から］──┘
```

规则只声明直接前项时显示一项。连接器接续显示共享路径与连接器；连续词尾按实际成员说明组成。分词恢复使用的多个原始 token 单独记录为来源范围。识别结果负责定位本句命中的分支；未命中的已配置分支仍可查看。

### 共用的て／で连接规则

「て／で」接续树属于连接形式自身的共享规则。补助动词用法通过规则引用使用该树；「いる」「しまう」「おく」等条目使用统一的连接器接续分类，并保留各自后项身份。共享树说明连接器的输入，补助词自身的适用条件由所属用法声明。

此树的前项词类、「て／で」连接形式和当前补助动词节点保持可见。动词、形容词、名词等词类入口不可折叠；入口内部具体活用类别及变化方式可以折叠。识别命中的细分路径默认展开，其他细分路径收起。连接形式和当前词条节点不可折叠。

```text
动词（一段、变格、五段清音）─ 连用形及音便 ─ て ─┐
助动词（被动、使役、ます、たい）─ 相应连用形 ─ て ─┤
イ形容词 ─ く ─ て ──────────────────────────────┤
否定ない ─ なく ─ て ────────────────────────────┤─ 补助用言本体
动词（五段浊音）─ 拨音便／イ音便 ─ で ──────────┤
ナ形容词 ─ 判断连用形 ─ で ──────────────────────┤
名词 ─ 判断连用形 ─ で ──────────────────────────┘
```

此图规定界面层级和折叠方式。「ない」的「なくて」归入て分支；「ないで」由独立连续词尾说明。「た」前的形容词连用形为「かっ」，随后连接「た」。各条前接路径须对应现有配置、运行结果和专项验收。

### 命中、折叠和诊断

- 主词类、连接形式、当前词条始终显示。
- 主词类内部活用型和具体词形变化可折叠；命中路径默认展开并高亮。
- 已识别路径按正常状态显示；候选路径保留命中线索并标明候选。
- 诊断说明本次分析为何处于候选状态，不改变规则图。
- 只有配置声明了多项依赖的规则才显示更长的上下文。

## 四、代表性显示稿

### 例一：読んでいる

```text
现有活用词条气泡
いる
补助动词 · 进行／状态持续
本句形式：読んでいる

在动词て形后表示动作持续，或动作结果形成的状态。

庭で花を育てている。
在庭院里种着花。
```

```text
新增接续方式气泡
补助动词递归关系
読む
└─ て形：読んで
   └─ いる：いる

前接规则：て／で
动词
└─ 五段动词（本句命中）
   └─ 连用形・拨音便：読ん
      └─ 接续助词「で」
         └─ 补助动词「いる」

形容词、名词等词类入口保持可见；各入口内部的细分变化可折叠。
```

### 例二：読みたい

```text
现有活用词条气泡
たい
助动词 · 愿望
本句形式：読みたい

表示说话人或询问对象想进行前项动作的愿望。「たい」本身按形容词型活用。

熱いお茶を飲みたい。
想喝热茶。
```

```text
新增接续方式气泡
［动词］─［连用形：読み］─＞【愿望助动词 たい】
```

### 例三：行かずに／高からずに

```text
［动词］──［未然形：行か］────┐
                                ├─＞【否定助动词 ず】─＞【に】
［形容词］─［未然形：高から］──┘
```

既有验收清单包含「行かずに」及「高からずに」。后者通过显式 input_recoveries 处理「高＋から」的分词恢复；两种来源范围分别保留，条目内部成员均为「ず＋に」。

## 五、规则内容和数据来源

| 展示内容                                 | 数据来源                                                                     | 用途                         |
| ---------------------------------------- | ---------------------------------------------------------------------------- | ---------------------------- |
| 词条名、词类身份、释义和例句             | grammar source、grammar catalog                                              | 现有活用词条气泡             |

| 本句表记、命中范围、父子关系、状态和证据 | Rust morphology artifact                                                     | 定位分支、展示当前路径和诊断 |

前端消费分析结果和规则配置，不重新实现接续判定。全局 rule_tree 用于说明六类实体的总览；单条词条的接续方式读取具体连接规则和连续规则。

历史构式标识继续通过迁移映射兼容。正式词条和查询身份指向「いる」「しまう」等本体；补助条目通过 connector 引用共享接续规则。展示元数据提供名称、顺序和折叠分组。connection_rules 的 source 标识文言 inputs 或谓语构式 prefix 的来源；完整性检查核对相应条件与原声明的一致性。connector_alternatives 为同一补助用法声明可替换的连接器，当前用于「名词＋に＋なる」和「ナ形容词＋に＋なる」。

## 六、额外识别规则设计清单

每个词条按具体用法逐项确认：

1. 词条本体、词类身份和语法功能。
2. 每条路径允许的前项词类和活用形；规则确实依赖时再限定活用型或词形。
3. 分别确定路径分支、依赖结构、条目内部成员及原始语素范围；连接器接续须声明其前项与连接器两级依据。
4. 连接形式由当前用法拥有，还是引用共享连接规则。
5. 每条路径的正例、相邻边界、输出状态、命中范围和词条归属。
6. 候选、冲突和未覆盖路径如何标记。

多路径用法的统一填写原则：

| 用法                       | 前接路径                                                     | 设计重点                                 |
| -------------------------- | ------------------------------------------------------------ | ---------------------------------------- |
| 否定「ない」               | 动词未然形；イ形容词连用形（く）；ナ形容词／名词经「で」接续 | 显示不同词类和变形，说明否定成分归属     |
| 文言否定「ずに」           | 动词未然形＋ず＋に；形容词未然形「から」＋ず＋に             | 区分条目成员、前项状态与分词恢复范围       |
| 过去「た／だ」             | 动词连用形及音便；イ形容词「かっ」；判断结构「だった」     | 分开表示前项形式、词尾变化和接续来源     |
| 判断收尾「だ／で／な／に」 | 名词或形状词前项及判断结构的不同收尾                         | 区分词条身份、连接形式和输出状态         |
| 缩约补助形式               | ている、てしまう、ておく的缩约、浊化和后续活用               | 复用共享连接规则，保留实际词面和本体身份 |

配置覆盖全部 150 个 operator，路径可直接声明或通过连接器引用。文言助动词按现有 inputs 填写，义务与禁止构式按 predicate_links 的 prefix 路径填写。正文与例句来自 grammar source、编译讲解及既有内置词条。此次收尾按用户要求检查条目完整性。

完整性统计为 89 个规则组、430 条路径，124 个条目直接声明规则，26 个条目通过连接器引用取得路径。接续结构分类分别为直接接续 84 项、连接器接续 30 项、连续词尾 18 项、谓语构式 12 项、词内活用 4 项、插入成分 2 项。分类、路径来源、概念正文、例句和既有 39 条样例的规则引用均已通过静态完整性检查。

## 七、维护顺序与完整性

### 维护顺序

1. 按实际用法确定词条本体、concept、operator 与依赖结构。
2. 填写路径的词类、活用形、必要的活用型与前项条件，并保留来源。
3. 连接器用法引用共享路径；词内活用读取本身状态；插入成分读取所属位置证据。
4. 维护语义说明和例句；形式相同而用法不同的成分分别路由到相应讲解。
5. 通过正式目录生成器更新编译语法资源。
6. 完成后运行 python -X utf8 scripts/check_morphology_connections.py，检查分类、路径、引用和词条内容。

### 验收条件

- 现有词典气泡与活用词条气泡的查询、内容和交互保持正常。
- 接续面板与活用词条面板沿用当前堆叠、定位和交互约定。
- 补助递归图与 parent chain、连接形式、词条本体和本句词形一致。
- て／で细分路径来自共享连接规则；补助词通过规则引用复用该树。
- 唯一路径线性显示；多路径和专门变形按声明显示分支。
- 主词类、连接形式和当前词条不可折叠；词类内部细分按约定折叠。
- 当前命中分支由分析产物定位；候选状态和诊断由识别结果提供。
- 多项前接依据路径或连接器声明保存；连续词尾成员与分词恢复范围分别记录。
- 词条释义不重复接续条件，接续图不复制词条正文。
