## 从阅读体验理解分析对象

用户提供的运行截图展示了同一分析内容的不同呈现方式。截图用于对应界面职责；字段和识别条件以代码为依据。

| 正文及界面 | 分析与查询的对应关系 |
| --- | --- |
| 「女の子でした」的右侧栏 | 「女の子」进入词汇查询；「でし＋た」形成 `copula_past`，显示断定过去、局部变化和接续树 |
| 「諦めてくれ」的侧栏 | 「諦め」对应「諦める」的词汇与连用形；句中图继续展示「て」及「くれる→くれ」的补助接续 |
| 「諦め」的窄屏抽屉 | 使用同一词典查询与说明内容，布局切换改变容器、尺寸和滚动方式 |
| 「済んだ」附近的浮动面板 | 词汇查询「済む」与过去说明并列组织，图中显示「済む→済ん」及「た→だ」的实际词形 |

词典中的中文义项、活用词条的功能摘要、句中接续图和可用接续规则树各有来源。正文中选择一个位置后，界面根据查询目标和活用命中取得相关内容；同一词法单位可以关联词汇查询及多个活用步骤。

## 身份、状态与规则

| 名称 | 含义 | 当前例子 |
| --- | --- | --- |
| 底层词性 | 来源 token 的词法分类，UniDic 保留四级 POS | `助動詞`、`名詞／普通名詞` |
| 词元身份 | 来源词元及其读法、ID，另保存本句出现形式 | `lemma`、`lForm`、`lemma_id` |
| 实体类别 | 状态机对语言对象的分类 | 动词循环类、插入语类等六类 |
| 词汇／功能角色 | 活用链在当前组合中的所有权 | 词汇「読む」与功能补助「いる」 |
| 活用状态 | 当前类别、连接形、精确活用型及原始活用形 | 动词连用形、形容词连用形 |
| operator 种类 | 已登记的语言操作 | `past`、`te_kureru`、`copula_past` |
| operator 实例 | 本次分析中一步操作及其实际范围、状态和证据 | 某处「た」的过去操作 |
| 接续路径 | 在规则组内确认的具体前接条件 | 五段动词的撥音便连用接续 |
| concept | 规则关联的知识及解说身份 | `morphology.tense.past` |
| occurrence | 正文中可解释的一次出现 | 带连接器及成员的补助构式命中 |
| 查询目标 | 词典服务或前端可选择的对象 | 整体词、内部词、活用或助词范围 |

原始 POS、状态机类别和显示名称分别保存。例如名词接判断词尾后形成名词谓语，接续许可可使用判断实体身份；原始名词身份继续用于词典和图示。六类实体、九种执行器分派值及六种接续结构分类分别服务语言分类、状态执行和路径组织，详见 L4、L5。

## 当前能力及实现边界

UniDic/Vibrato 提供词法及活用字段，GiNZA 提供自身的正式词元、UD 依存、文节、句子、小句和实体结果。两者在准备后的正文坐标中对齐。活用状态机消费词法和必要的局部结构证据，输出链、步骤、路径和出现范围。

构词模块根据正式词界与 compound 关系生成候选；文节和小句模块映射已有来源结构；词典模块继续确认词汇范围及可查询对象。来源结构、候选词汇和最终查询对象在数据上分别保留。

普通统一分析中的 `grammar` 保存基础功能语素候选，`expression` 初始为空，`application` 使用默认空对象。通用 grammar 规则应用保留独立实现，规则预览有调用入口。活用识别及其词条说明已进入阅读路径。原 grammar 整体流程和语法库界面设计的状态见 [L6](entries.md#现有查询服务与过时设计)。

## 代码与维护顺序

分析装配入口为 [unify.rs](../../crates/readux-nlp/src/unify.rs)，统一协议为 [model.rs](../../crates/readux-nlp/src/model.rs)。本机调度在 [analysis_engine.rs](../../crates/readux-core/src/analysis_engine.rs)，前端对应类型在 [nlp.ts](../../src/types/nlp.ts)。字段变更需同时核对本机产物、查询服务、静态制作及前端消费。

规则维护顺序为真实输入与来源字段核实、规则与状态设计、词条及解说维护、配置编译、相关分析快照更新、最终针对性验证。纯文档整理集中检查内容依据、路径和引用。

L0–L6说明结构与主要契约。规则细节进一步整理为[分类与编写指南](morphology_rule_categories.md)及[显示规范与修订设计](morphology_display_conventions.md)，覆盖学校语法与功能细类、同形区别、内部字段和样例、名称讲解及前接树编排。后续实施项见 [L5](morphology_configuration.md#规则细节交接)。
